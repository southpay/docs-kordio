## Error envelope

Failures return a JSON body with a machine-readable `code`, a human `message`, an actionable `hint`, and a `docs_url` that links straight to the matching anchor on this page. Some errors add a `param` naming the offending field and a typed `details` map.

```json
{
  "error": {
    "code": "unbalanced",
    "message": "transaction does not balance",
    "hint": "debits must equal credits per currency in the transaction",
    "docs_url": "https://docs.kordio.io/errors#unbalanced"
  }
}
```

Switch on `code`. It is stable across versions. Do not parse `message`; it is for humans and may change. The HTTP status mirrors the `code`, listed per entry below.

## General

### invalid_request

`422` - The request payload is malformed or missing required fields. Check the request against the [API reference](/api-reference/introduction). When a specific field is at fault, `param` and `details.fields` identify it.

### unauthorized

`401` - No valid access token was presented. Include a valid Bearer token issued by `POST /oauth/token`.

### forbidden

`403` - The access token is valid but not permitted to perform this operation.

### not_found

`404` - The resource does not exist. Verify the id and that it belongs to your tenant and ledger.

### rate_limited

`429` - You are sending requests too quickly. Back off per the `Retry-After` header and try again.

### internal_error

`500` - An unexpected error occurred. Retry the request; if it persists, contact support.

## Control layer

The agent API answers a denied decision with `403` and the whole decision in the body, not just a code. The rule that refused is in `decision.rule`, and `decision.headroom` reports what is left on every limit that applied, so an agent can pick a cheaper path instead of retrying into the same wall.

```json
{
  "data": { "id": "9b2e…", "state": "denied" },
  "decision": {
    "outcome": "denied",
    "rule": "cost_cap",
    "detail": { "max_cents": 50000, "requested_cents": 120000 },
    "headroom": { "session_remaining_cents": 380000 }
  }
}
```

The rules that can refuse:

| `decision.rule` | Why |
| --- | --- |
| `session_active` | The session is exhausted or closed. Open a new one. |
| `runtime_scope` | The runtime key is not scoped for this `action_type`. |
| `session_budget` | The action does not fit the remaining session envelope. |
| `cost_cap` | Over the per-action ceiling. |
| `spend_window` | Over the rolling-window cap. |
| `monthly_spend_cap` | Over the calendar-month cap. |
| `rate_limit` | Too many actions in the window, regardless of amount. |
| `action_allowlist` | This action type is not permitted. |
| `resource_allowlist` | This counterparty or resource is not permitted. |
| `not_allowlisted` | An allowlist-mode policy matched no `allow` rule. |
| `spend_token` | The token is spent, expired, over its ceiling, or pinned to another counterparty. |

An `approval_threshold` never appears here. It does not refuse; it answers `202` and holds the action. See [holding spend for a person](/agents/approvals).

### missing_idempotency_key

`400`. `POST /v1/agent/actions` and `POST /v1/agent/payment_intents` require an `Idempotency-Key` header. Reuse the same key on a retry and Kordio replays the original decision rather than reserving budget twice.

### live_provider_unavailable

`503`. A live payment provider could not be reached. The decision stands and the reservation is held; retry the execution rather than re-authorizing.

<Warning>
  A `403` from the agent API is a policy answer, not a transport failure. Do not retry it with a fresh idempotency key: that asks the same question again and, for a held action, asks a person twice. Change the action or change the policy.
</Warning>

## Ledger semantics

### missing_idempotency_key

`400` - A write was sent without the required `Idempotency-Key` header. Supply a key that is unique per logical request. See [Idempotency](/concepts#idempotency).

### unbalanced

`422` - The transaction's debits do not equal its credits in some currency. Debits must equal credits per currency. See [Double-entry](/concepts#double-entry-balanced-per-currency).

### currency_mismatch

`422` - A posting's currency does not match the account it targets. Every posting must use its account's currency.

### unknown_account

`422` - A posting references an account that does not exist. Create the account before posting against it.

### already_exists

`409` - A resource with the same identifier or idempotency key already exists. Pick a different id, or patch the existing resource.

### already_reversed

`409` - The transaction has already been reversed. Fetch the existing reversal via `GET /v1/transactions/{id}` and inspect `reversed_by`.

### immutable_field

`409` - You tried to change a field that cannot change after creation (for example a posting's economic columns or an account's currency).

### insufficient_funds

`422` - The source account would exceed its overdraft policy. The write was not applied.

### period_closed

`409` - The `value_date` falls in a closed period. Book with a `value_date` in the current open period, or reopen the period.

### precondition_failed

`409` - An `If-Match` or `If-Unmodified-Since` precondition was not satisfied.

### duplicate_external_ref

`409` - An `external_ref` with this (rail, kind, value) is already attached to another transaction.

### partial_refund_exceeds_original

`422` - The refund amount plus prior partial refunds in this currency exceeds the original gross. See `details.remaining_by_currency` for the remaining refundable amount.

### refund_currency_required

`422` - The original transaction is multi-currency, so you must pass `currency` to disambiguate which leg you are refunding. See [Multi-currency](/concepts#multi-currency).

### rotation_in_progress

`409` - The previous secret is still inside the 24-hour overlap window. Wait, or pass `?force=true` to destroy it now.

### webhook_endpoint_disabled

`409` - The webhook endpoint is disabled. Re-enable it via `PATCH /v1/webhook_endpoints/{id}` before sending.

### account_template_unknown

`422` - The referenced account template does not exist. Create it first via `POST /v1/account_templates`, or omit `template` to use raw account fields.

### tenant_suspended

`403` - Your tenant is suspended. Contact support.

### invalid_state

`409` - The resource is not in a state that permits this operation.

### fresh_authentication_required

`401` - This destructive operation requires recent authentication. Re-authenticate within 5 minutes before retrying.

## OAuth

These follow RFC 6749 section 5.2 at the token endpoint.

### invalid_client

`401` - The `client_id` or `client_secret` is wrong, or the client is disabled. Verify your credentials.

### invalid_grant

`422` - The `grant_type` or its parameters are invalid.

### invalid_scope

`422` - The requested scope is not granted to this client.

### unsupported_grant_type

`422` - Only `client_credentials` is supported today.

### insufficient_scope

`403` - The access token lacks the scope this endpoint requires. See [Scopes](/authentication#scopes).
