Give an agent a credential and it can spend. Nothing between it and the rail asks whether it
should. The card sees a valid card, the API key sees a valid key, and both are right, because
neither was ever told what this agent is for.

<Info>
  **The decision boundary.** The moment something non-human can initiate spend you would want
  to review, you are at the layer this product serves. Before that, a hard-coded cap in your
  own code is fine. After it, the question is not whether you have a control layer but
  whether it can be bypassed, and whether it can prove what it permitted.
</Info>

## What Kordio is

Kordio is the control layer for AI agents that transact. Before the agent pays a vendor, buys
on a marketplace, books a trip, or calls a paid tool, it asks, and gets an answer in the same
request: allowed, needs a person, or denied, naming the rule that decided and reporting the headroom left on every limit. Allowed
answers come back signed, so whatever executes can verify the authority instead of trusting
the agent that carries it. Kordio holds no funds, no accounts, and none of your credentials.
It is a required signer, never a custodian.

The same engine governs any action type, not only payments, and it is not tied to a payment
rail. An action type is a dotted string like `payment.create`, `order.place`, `booking.create`
or `tool.invoke`. Kordio never executes any of them, so nothing in the model assumes a card, a
bank, a chain, or a marketplace on the other side. A runtime's caps, windows and allowlists apply
across all of them together, so spend on one consumes headroom for the other.

## The ledger underneath

Where a workspace has the ledger enabled, every decision the control layer takes is mirrored
as balanced postings in a double-entry ledger: accounts, derived balances, point-in-time
history, and reconciliation as a first-class operation. The control layer decides what may
happen, and the ledger records what did. Check Billing in the console for whether it is on for
you.

It is included in every tier rather than sold separately, so there is one price for the
control layer and the books underneath it. It is also a real general-purpose ledger rather
than an audit log wearing accounting vocabulary, and you can use it directly. The projection
never sits in the authorization path, so the ledger being slow cannot delay or change a
decision.

## Is this for you?

**Yes, if something non-human can start a payment or a paid API call.** An agent buying
supplies, booking freight, managing ad budget, or just burning through model and tool spend
at a rate nobody predicted. You want a rule that runs before the money moves and a record
afterwards that names what permitted it. That is [spend control](/agents/why).

**Yes, if you also need an auditable money system of record.** A treasury product, a
marketplace splitting funds, an FX desk, a SaaS company billing its own usage. That is the
[ledger](/ledger/why), and it comes with every tier at no extra price.

**No, if you only need bookkeeping for your own company's taxes and statements.** That is
what accounting software is for.
