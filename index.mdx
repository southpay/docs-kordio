Kordio is two APIs on one host. Spend control decides what your agents are allowed to do
before they do it. The ledger keeps the books that prove what happened. They share a host,
an account, and a set of test-mode credentials, and you can use either one on its own.

<CardGroup cols={2}>
  <Card title="Spend control" icon="shield-check" href="/agents/quickstart">
    Your agent asks before it spends. You get `allowed`, `requires_approval`, or `denied` in
    the same request, naming the rule that decided, plus a signed grant your executor can
    verify without trusting the agent that carries it.

    **Start here if** something non-human can start a payment or a paid API call on your
    behalf.
  </Card>

  <Card title="Ledger" icon="book-open" href="/ledger/quickstart">
    Double-entry accounting over HTTP. Post balanced transactions, read balances and
    statements at any instant, and reconcile against the outside world. Debits equal credits
    per currency or the write is rejected.

    **Start here if** you need an auditable record of what money meant, separate from
    whatever moved it.
  </Card>
</CardGroup>

## The call each one is about

Developers pick faster from a request shape than from a paragraph.

<CodeGroup>

```bash Spend control
curl -X POST https://api.kordio.io/v1/agent/actions \
  -H "Authorization: Bearer $KORDIO_RUNTIME_KEY" \
  -H "Idempotency-Key: order-4471" \
  -d '{"session_id":"3f1c...","action_type":"payment.create","cost_cents":12000}'
# → 201 allowed | 202 requires_approval | 403 denied
```

```bash Ledger
curl -X POST https://api.kordio.io/v1/transactions \
  -H "Authorization: Bearer $KORDIO_TOKEN" \
  -H "Idempotency-Key: invoice_001" \
  -d '{"postings":[
        {"account":"cash:usd","amount":"1000","currency":"USD","direction":"debit"},
        {"account":"revenue","amount":"1000","currency":"USD","direction":"credit"}]}'
```

</CodeGroup>

## Which credential do I have?

The most common way to arrive here is holding a string somebody else generated.

| If you are holding | You want |
| --- | --- |
| A key starting `krt_` | [Spend control: runtime keys](/agents/authentication) |
| A `client_id` and `client_secret` | [Ledger: OAuth client credentials](/ledger/authentication) |
| A dashboard login and nothing else | [Getting your credentials](/agents/authentication#getting-your-credentials) |

## Using both?

Start with spend control. Where a workspace has both, every reservation it takes is mirrored into
the ledger as balanced postings, so agent spend arrives pre-reconciled. Each workspace owns its
books and each runtime owns an account inside them. You do not write those postings yourself, and
you do not need to read the ledger docs to ship the control layer.

The control layer decides what may happen; the ledger records what did. Each is a complete
API on its own. The control layer just happens to be the ledger's first customer.

<Info>
  **How the ledger is packaged.** It comes included on the higher plans, and is available as an
  add-on on the rest. Check **Billing** in the [console](https://app.kordio.io) for what your
  workspace has today.
</Info>
